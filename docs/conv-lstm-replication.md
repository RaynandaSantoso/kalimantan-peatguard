# CNN–ConvLSTM replication specification

Primary reference: `papers/mahdiyasa2026.pdf`, Mahdiyasa et al., *A Calibrated Spatio-Temporal Machine Learning Model for Tropical Peatland Fire Risk*, DOI 10.1016/j.nhres.2026.07.007. Page numbers below count the PDF cover as page 1. This specification was extracted before implementing the architecture.

## Completed experiment: saved model evaluation (2026-10-28)

The completed experiment evaluates the validation-selected model without a full-year refit. See [findings and final scope](findings.md). **Weight fitting and scaler fitting: 2020-01-01 through 2023-09-30. Validation: 2023-10-01 through 2023-12-31. Evaluation: all of 2024.** October–December labels selected the checkpoint and early-stopping point; they were not used for gradient updates. Earlier feature-only context may cross the split boundary. This training cohort differs from the paper's full 2020–2023 fit and from section 4 of the classical baselines. It must not be described as an exact same-training-cohort replication or comparison.

The run at `data/interim/conv_lstm/20261027T155222671757Z` completed at epoch 43, with the lowest validation weighted loss at epoch 23 (zero-based CSV index 22). `development_best.weights.h5` contains the weights restored by EarlyStopping; `latest_development.weights.h5` contains the stopping-epoch checkpoint. The saved best file also contains optimizer slots from the stopping point; it is used for inference only. Section 5.2 now loads the best checkpoint and `development_scaling` arrays; it does not call `fit`. The older `full_training_scaling` arrays are historical preparation artifacts and must not be used with this checkpoint.

Section 6 evaluates raw predictions on all valid 2024 cell-days and uses a constant frequency estimated only from the actual January 2020–September 2023 fitting targets. Prediction runs use `training=False`, keep optimizer iterations unchanged, and never update weights or batch-normalization statistics. Results and an explicit split/checkpoint/scaler record are written to `development_2024_evaluation/` within the saved run. No calibration is fitted as part of this raw evaluation. Section 7 fits isotonic regression on January–June 2024 and evaluates on July–December; this separate experiment is enabled by default.

The reported-method extraction below records published settings and the final reconstruction choices. The reported results use the validation-selected checkpoint and its September-fitted scaler without a full-year refit. The original notebook was preserved in the run as `notebook_before_2024_evaluation.ipynb`.

## 1. Reported methods and reconstruction decisions

| Component | Local paper evidence | Implementation |
| --- | --- | --- |
| Spatial unit | §2.2.2, pp. 14–16: 5 × 5 km, min–max continuous scaling, one-hot land cover | Existing LAEA 5 km candidate BIG grid; north-up maps recovered from signed lattice IDs. Retain 21 existing predictors. The candidate mask and source proxies are reconstruction differences, not an exact match to the authors' grid. |
| Fire label | §2.2.1 p. 9 and §2.2.2 p. 16: MODIS confidence >80, any hotspot in cell | Existing eligible daily binary detection labels. Missing records and cells outside the candidate mask never become supervised negatives. |
| Chronology | §2.3.2 p. 22: paper fits 2020–2023 and evaluates 2024 | Local weights/scaler fit Jan 2020–Sep 2023; Oct–Dec 2023 selects the checkpoint; evaluate 2024. No full-year refit. The already-inspected 2024 period is not an untouched test. |
| Input timing | §2.3.1 pp. 19–20: consecutive feature maps; conceptual diagram mentions fire occurrence | Exact sequence length, target offset, stride, historical-fire lag and boundary policy are absent. Choose seven daily maps ending on target day, stride one, no fire-label input. This is retrospective same-day classification with horizon zero, not a future-fire forecast. No same-day labels enter predictors. |
| Boundaries | Not specified | Drop first six days of the available 2020 calendar; require contiguous daily positions, never wrap or pad time. Allow earlier feature-only context across year/split boundaries, including December 2023 for January 2024. Missing target-cell history excludes that cell from loss/scoring; masks also distinguish missing neighboring inputs. |
| First layer | §2.3.2 p. 22 | ConvLSTM2D(32, 3×3, tanh, recurrent sigmoid), then batch normalization and Dropout(0.30). |
| Decoder | §2.3.2 p. 22 | Conv2D(64, 3×3, ReLU), batch normalization, Dropout(0.30), then Conv2D(32, 3×3, ReLU), batch normalization. |
| Output | §2.3.2 p. 22 | Conv2D(1, 1×1, sigmoid). |
| Architecture omissions | §2.3.1 describes CNN before recurrence, but §2.3.2 explicitly starts with ConvLSTM | Follow the explicit implementation order; do not invent a preceding CNN. Choose same padding, final recurrent state only, channels-last, stride one, ordinary dropout, no pooling, no state carry between samples. Other Keras defaults and installed version are recorded with each run. |
| Missing spatial data | Not specified | Features outside observed support are zero-filled. Add separate static-domain and daily-observed mask channels (23 total channels). Supervision requires known target and complete local feature history. Mask channels are an explicit reconstruction addition. Batch normalization/convolutions still see background; loss masking does not remove all boundary effects. |
| Weighted loss | Eq. (2), p. 17; §2.3.2 and Table 2, pp. 22–23 | Positive weight 75, negative weight 1. Eq. (2) is a sum; use its sum divided by the number of valid supervised cell-days in each batch to make gradient scale independent of background area. Do not divide by class-weight sum. Packed label and mask are passed to a custom loss. |
| Training | §2.3.2 p. 22 | Batch size 2, maximum 70 epochs and early stopping patience 20. Deeper search patience 30 is reported but its maximum epochs and search configuration are not given; no deeper search is reconstructed. |
| Training omissions | Optimizer, learning rate, stopping monitor, validation membership, seed, initialization details are absent | Adam at 0.001, seed 42. Select epoch count using weighted loss on Oct–Dec 2023 after fitting Jan 2020–Sep 2023; fit scaling on that earlier fitting subset for selection. Retain the selected development network and September-fitted scaler for 2024 scoring. The network was not refitted on all of 2020–2023. No 2024 labels select epochs. |
| Class-weight selection | §2.3.2/Table 2, p. 23 | Authors selected 75 using the testing period, from 10, 25, 50, 75, 100. Retain published 75 without searching again; this is a published test-informed choice, not independent validation of that choice. |
| Calibration | §2.3.1, p. 21, Eqs. (12)–(14) | Isotonic regression. Calibration cohort/split and fitting-versus-scoring separation are unspecified. Report full-year raw scores first. Exploratory calibration fits a new mapping on Jan–Jun 2024 and compares raw/calibrated predictions only on Jul–Dec; never reuse baseline calibrators. This is a documented extension, not the paper's recoverable protocol. |
| Forecasts | §3.2, pp. 27–30: 3- and 10-day examples | Predictor availability, future weather treatment and label timing/aggregation are not specified. Do not fabricate these forecasts from retrospective predictors. |

## 2. Current export and preprocessing contract

Use only `data/interim/model_table/train_2020_2024.parquet`, identified and checksummed through `prepared_dataset.json` and its source build. Never fall back to legacy exports. Inspect the saved scaler and build descriptor. The existing `_encode` implementation in `peatguard/datasets.py` uses an unclipped affine transform; its current four nonconstant ranges were fitted on 2020–2024. Invert that transform using its saved parameters, fit new raw-unit ranges on the chosen training dates only, then apply those ranges to all feature dates without clipping. Constant features scale to zero by the established preparation contract. Save both source and reconstructed ranges.

Use a compact disk-backed daily `(date, study-cell, predictor)` store, constructing full spatial maps only for the current batch. The sequence collection is never materialized. Validate unique keys, binary labels, finite features, one-hot categories, recognized lattice addresses, target dates and observation masks. Calendar holes remain holes. Model inputs contain no target channel. Store prediction keys explicitly so evaluation is independent of table row order.

## 3. Reported results and interpretation limits

- §3.1 pp. 23–24: headline ROC–AUC **0.845**, raw Brier approximately **0.198**, isotonic Brier approximately **0.011**. These are reference results, not reproduced scores.
- Table 2 p. 23: weight 75 precision **0.699**, recall **0.885**; threshold and scoring support are not stated. Do not claim comparability to an assumed 0.5 threshold.
- §3.1 pp. 24–25: dry (May–October) AUC **0.811**, Brier **0.088**; wet (November–April) AUC **0.822**, Brier **0.027**. These seasonal Brier values cannot average to the stated full-year 0.011 on the same scoring support/calibration; the paper does not resolve this discrepancy.
- §3.2 pp. 29–30: three-day AUC/precision/recall **0.836/0.688/0.842**; ten-day **0.784/0.670/0.764**. No forecast claim is made by this same-day reconstruction.

Evaluate raw ROC–AUC, average precision (also relative to prevalence), Brier and a training-frequency constant on exactly the same valid cell-days. Report TP/FP/FN/TN at fixed 0.5 and descriptive whole-year alert targets 100, 1,000, 10,000, including ties. Alert budgets computed from evaluation scores are descriptive ranks, not independently chosen deployable thresholds. Report excluded cell-days and coverage. Spatial/temporal context differs from the classical inputs, so an improvement does not isolate an architecture effect. A false alarm denotes no qualifying recorded detection, not verified fire absence. There is no claim of exact numerical reproduction or operational warning readiness.

## 4. Running and implementation verification

Install the additional neural runtime with `.venv/bin/python -m pip install -r requirements-conv-lstm.txt`, then select that environment in `cnn_conv_lstm.ipynb`. Sections 1–4 handle configuration and preparation/alignment checks; the disposable smoke fit runs only in new-run mode. The notebook defaults to `RUN_MODE = "saved"`: sections 2–3 load/check the saved September-fitted arrays, section 4 skips the disposable smoke fit, section 5.1 displays the completed combined training history, section 5.2 loads the selected checkpoint, and section 6 evaluates it. There is one training path, guarded by `RUN_MODE = "new"`. Temporary manual restore/resume/pause cells have been removed from the main notebook; their original state is archived locally as `notebook_before_cleanup.ipynb` in the saved run. Section 7 is a separate calibration experiment. No full-year refit is performed. Only new-run mode creates a new UTC-named directory under gitignored `data/interim/conv_lstm/`. Saved mode reuses the explicitly configured run and does not retrain. Calibration is enabled by default (`RUN_CALIBRATION = True`); set it to False to skip. Section 7 can also run alone in a fresh kernel from saved raw predictions and the raw evaluation record, without importing TensorFlow or repeating inference. Set `RUN_DIR` to calibrate another completed run. It checks checkpoint/scaler fingerprints and validates dates, labels and keys before fitting; it saves the mapping, keyed later-cohort predictions, metrics/counts and a separate fingerprinted `calibration_spec.json`. The original raw evaluation record remains unchanged. A fresh clone does not include the local arrays or weights: acquire/prepare the documented sources and choose new-run mode, or provide the complete saved run. No fallback dataset is loaded. Training uses deterministic chronological batches; sequence hidden states reset for each sample. The completed run's Keras configuration is saved as `development_architecture.json`, and its selected weights as `development_best.weights.h5`. To reload for inference, reconstruct with `build_model(..., spatial_shape=(168, 217))` using the recorded length/channels/settings, then load the weights; use the saved reconstructed scaler and original cell-address order for the features. Weight files also contain optimizer state; inference does not require restoring it.

Implementation verification on 2026-10-27 used TensorFlow 2.21.0 / Keras 3.15.1. The real export produced 1,827 daily positions and a 168 × 217 rectangle containing 3,512 study cells. The batch shape was `(2, 7, 168, 217, 23)`. Removing the six initial context days excluded 21,072 training cell-days, leaving 5,109,960 supervised training cell-days and all 939 positives. All 1,285,392 evaluation cell-days and 70 positives retained complete history. Full-map inference and a crop gradient update passed. That initial implementation check produced preparation/smoke results only. Subsequent full-cohort training, raw evaluation and isotonic calibration are complete; their history and results are retained in the notebook and saved-results directory.

Regression tests (`.venv/bin/python -m unittest discover -s tests -p 'test_conv_lstm.py' -v`) cover shuffled-key spatial alignment, chronological boundary context, training-only affine reconstruction, missing days/labels/features including constant features, domain masking, duplicate/unknown keys, one-hot validation, exact weighted-loss reduction and masked gradients, published layer settings, a streamed neural fit, keyed predictions, metric/count calculations, and saved-weight reload. The unchanged notebook training, epoch-selection, raw-evaluation and separate-calibration cells were also exercised on a small synthetic cohort with a two-epoch cap; synthetic scores are not study results.

## Recorded isotonic calibration (2026-10-28)

Section 7 was executed on the saved epoch-23 model's raw predictions. Calibration fitting used January–June 2024: 639,184 cell-days and 9 positives. Evaluation used July–December 2024: 646,208 cell-days and 61 positives. The network was not retrained; 2025 data was not loaded. The mapping uses scikit-learn's [`IsotonicRegression(out_of_bounds="clip")`](https://scikit-learn.org/stable/modules/generated/sklearn.isotonic.IsotonicRegression.html). Fitting and evaluation are disjoint, consistent with the [probability calibration guide](https://scikit-learn.org/stable/modules/calibration.html).

| Version | July–December Brier | ROC–AUC | Average precision |
| --- | ---: | ---: | ---: |
| Raw | 0.0124778301 | 0.860607 | 0.002492 |
| Isotonic | 0.0000942723 | 0.841654 | 0.002069 |
| Training-frequency constant | 0.0000943890 | 0.500000 | 0.0000944 |
| Calibration-frequency constant | 0.0000943944 | 0.500000 | 0.0000944 |

The isotonic Brier score is only 0.129% lower than the calibration-frequency constant. Both ranking metrics decrease, and at score ≥0.5 there are no alerts. The descriptive 10,000-alert target includes 14,850 tied scores, finding 32 positives with 14,818 false alarms; the raw version finds 27 with 10,000 alerts. These unequal alert counts do not demonstrate better detection at the same budget. Nine calibration positives, seasonal shift and previously viewed outcomes limit this exploratory result. Compare calibration versions within this later cohort, not against the full-year raw score.

The fitted mapping, keyed predictions and small outputs are saved under the run's `development_2024_evaluation/`. Reviewable metrics, alert counts and a fingerprinted calibration specification are also retained under `results/conv_lstm/validation_2023q4_evaluation_2024/`. Raw-stage artifacts retain their original provenance, including their historical no-calibration status; the separate calibration specification records completion of this later stage.

The standalone cell is covered by `tests/test_notebook_calibration.py`: changing later-cohort labels leaves the mapping unchanged; exported scores match the reloaded mapping; clipping and artifact fingerprints are verified; invalid dates, duplicate keys, invalid labels/probabilities, single-class halves, overlapping model selection and changed checkpoints fail before export.
